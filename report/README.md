# 경기 분석 리포트 (프로토타입)

팀 파이프라인이 만든 `tracks.json`(선수·공 좌표)으로 경기 후 읽을 리포트를 만든다.
좌표만 쓰고 영상·사진은 넣지 않는다. 의존성은 numpy 하나 (팀 코드는 import 하지 않음).

## 실행

```powershell
cd D:\02_Projects\futsal\calibration
$env:PYTHONIOENCODING='utf-8'
.\.venv\Scripts\python.exe report\make_report.py <tracks.json> [--summary summary.json] [--out 출력폴더] [--title "제목"]
    [--players A=5 B=5] [--high-intensity] [--min-seen 초]
```

- `--players`: 팀별 실제 선수 수 (교체 선수 포함, 팀 이름은 tracks.json 의 `team` 값과 같게). 아래 “인원 정보” 참고
- `--high-intensity`: 고강도 거리(≥4 m/s)를 HTML에도 표시. 기준이 아직 정해지지 않아 기본은 숨김 (report.json 에는 항상 있음)

- 출력: `report.html` (외부 리소스 없는 한 파일, 휴대폰 화면에 맞춤), `report.json` (계산한 숫자 전부, 앱에서 그릴 때 사용)
- `--out` 이 없으면 tracks.json 옆 `report/` 폴더
- 개발용 합성 경기: `.\.venv\Scripts\python.exe report\synth_match.py out.json --minutes 40 --seed 1`
  (전·후반 진영 교체, 교체 선수, 위치 흔들림, 미검출, ID 조각, 순간이동, 공 포함)
- 테스트: `.\.venv\Scripts\python.exe -m pytest tests/test_report.py -q`

## 섹션

| 섹션 | 내용 |
|---|---|
| 경기 개요 | 경기 시간, 팀별 총 이동 거리, 1명당 거리(인원 정보가 있을 때) 또는 주요 ID 평균, 진영 추정 결과, 팀 비교 표 |
| 선수별 기록 | 추적 시간, 거리, 분당 거리, 평균 속도, 최고 속도(추정), 스프린트(≥5.5 m/s 1초 이상), 5분 단위 거리 (고강도 거리는 `--high-intensity` 일 때만) |
| 시간대별 활동량 | 5분마다 팀 이동 거리 (경기가 15분보다 짧으면 1분), 전·후반 거리 |
| 히트맵 (팀) | 팀별, 1 m 칸. 진영 추정이 되면 “항상 오른쪽으로 공격” 좌표로 돌려서 그림 |
| 구역 점유 | 공격 방향 기준 수비/중간/공격 1/3, 좌/중/우 + 코트 절대 위치 3×3 비율 |
| 평균 위치와 팀 형태 | 전·후반 평균 위치(절대 좌표), 폭·길이(필드 선수 y·x 범위 중앙값), 동료 간 평균 거리 |
| 히트맵 (선수) | 주요 ID마다 2 m 칸 작은 그림 |
| 공 위치 | 공이 있을 때만. 위치가 있는 프레임 비율, 어느 쪽 반에 있었나 — **검증 전 참고값** |
| 데이터 품질 | ID 수, 짧게 잡힌 ID(접힌 목록, 넣었다면 더해졌을 거리), 실제 인원 대비 주요 ID 수, 보인 시간 비율, 순간이동 수, 보정 오차, 계산 방법 |

## 계산 방식 (요약)

- **궤적 정리**: 위치 흔들림을 추정하고, 불가능한 이동(순간이동 = ID 잘못 이음)과 2초 넘는 미검출에서 끊은 뒤,
  짧은 빈칸은 직선으로 메우고 0.6초 이동평균을 두 번 적용 (흔들림이 크면 창을 넓힘).
  팀 시뮬레이터 정답과 비교해 필드 선수 거리 오차 약 ±1.5%, 골키퍼 -2~-8%.
- **최고 속도**: 한 프레임 최댓값은 흔들림·순간이동 때문에 수십~수백 m/s 까지 튀어서 쓰지 않는다.
  정리된 궤적에서 0.5초 동안 계속 유지한 가장 빠른 속도를 “추정값”으로 낸다 (정답보다 0~0.8 m/s 낮게 나오는 편).
- **짧게 잡힌 ID**: 보인 시간이 `clamp(경기의 10%, 30초, 120초)` 미만인 ID. **모든 집계에서 뺀다** — 선수 표·순위·
  하이라이트·선수/팀 히트맵·팀 총 거리·구역·팀 형태·시간대별 활동량. 데이터 품질 섹션에만 개수, 기준,
  넣었다면 더해졌을 거리(비율·팀별)를 보여준다.
- **진영 추정**: 1분마다 두 팀 평균 x 를 비교해서 순서가 한 번 뒤집히는 곳을 후반 진영 교체로 본다.
  팀은 자기 골대 쪽에 더 가까이 있다고 가정한다.
- **골키퍼 추정**: 추적 시간의 70% 이상을 골라인 6 m 안에서 보낸 ID (팀 형태 계산과 하이라이트에서 뺌).
- 좌표: 원점은 코트 모서리, x 0~40 (골대 방향), y 0~20. 그림에서 y 는 위쪽.

## 인원 정보 (`roster`)

앱이 촬영 전에 팀별 선수 수를 받는다. 리포트는 다음 순서로 찾는다: `--players` → tracks.json → summary.json.
파이프라인/앱 쪽에서 넣을 키 (최상위):

```json
"roster": {"A": 5, "B": 5}
```

- 팀 이름은 `players[].team` 값과 같아야 한다. 숫자는 그 경기에 뛴 실제 선수 수 (교체 선수 포함).
- 쓰는 곳: 팀 “1명당 거리” = 팀 총 거리 ÷ 실제 인원 (표에 그렇게 적음), 데이터 품질에서 주요 ID 수와 비교
  (예: “팀 B: 주요 ID 7개, 실제 선수 5명 → 한 선수의 ID가 여러 개로 나뉘었을 수 있음”).
- ID를 합치거나 고르는 데는 쓰지 않는다 (ID 정리는 추적 담당 몫).
- 없으면 1명당 거리와 인원 비교 없이 나머지는 그대로 나온다.

## 알려진 한계

- ID 조각이 많으면(실제 53분 경기: 실제 12명에 ID 24개) 선수별 기록은 “ID별 기록”일 뿐이다. 조각을 같은 선수로
  합치는 기능은 없다. 이름(`name`)이 없으면 `ID n` 으로 표시.
- “추적 분”은 그 ID가 추적된 시간이라 실제 출전 시간과 다를 수 있다 (가려짐, 조각).
- 진영 추정은 팀 평균 위치에 기대므로 한쪽으로 몰린 경기나 팀 판별이 틀린 데이터에서는 틀릴 수 있다.
  추정이 안 되면 절대 위치로만 보여준다. 전·후반이 한 파일에 없으면 교체도 못 찾는다.
- 공 위치는 아직 검증 전 (떠 있는 공은 바닥에 잘못 투영). 점유율이 아니라 “어느 쪽 반에 있었나”만 본다.
- 코트 좌표 오차 약 0.15 m (가까운 쪽) ~ 0.3 m (먼 쪽). 먼 쪽 골키퍼처럼 흔들림이 큰 궤적은 거리·속도 오차가 크다.
- 고강도(4 m/s)·스프린트(5.5 m/s) 기준은 아마추어 풋살 기준으로 정한 값이라 실제 데이터로 조정이 필요하다.
